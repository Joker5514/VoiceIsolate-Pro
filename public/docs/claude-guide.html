System Overview

PRIVACY-FIRST

Zero Cloud

All audio is processed on-device. No audio ever leaves the browser.

Runtime

Web Audio API + ONNX Runtime Web. WebGPU acceleration with WASM fallback.

Cross-Platform

Web via Vercel + native Android (API 23+) and iOS (14.1+) via Capacitor 8.

Engineer Mode

52 sliders across 8 tabs, 6-panel diagnostics, 3D spectrogram visualization.

Canonical version lives in package.json#version. When bumping: update package.json, README.md, CLAUDE.md, capacitor.config.json, then run pnpm mobile:sync-version.

Critical Architectural Rules

CI ENFORCED
These rules are enforced by scripts/validate.js and the CI pipeline. Violating any of them breaks the build.
Rule 1
Single-Pass Spectral Architecture
Within any single processing path there is exactly one forward STFT and one iSTFT. All spectral operations occur in-place between them. Never add a second STFT/iSTFT pair.

Rule 2
AudioWorklet Ownership
Only pipeline-orchestrator.js calls audioContext.audioWorklet.addModule(). Never register AudioWorklet modules from app.js, dsp-worker.js, or any other file.
Rule 3
ML Worker Ownership
Only pipeline-orchestrator.js spawns the ML worker. Never create it from app.js or other orchestration files.
Rule 4
Third-Party Libraries: Local Only
ONNX Runtime → always /lib/ort.min.js — NEVER a CDN URL
Three.js → always /lib/three.module.min.js via importmap — NEVER a CDN URL
CSP in vercel.json enforces this.
Rule 5
Privacy: No External Audio Calls
Audio data must never leave the browser. The default processing mode is entirely local — no audio is sent to any server. analytics.js logs locally only. The optional api/nim/ module provides NVIDIA NIM cloud inference as an opt-in feature; it is disabled by default and requires explicit configuration to activate. No NIM endpoints are called unless the user intentionally enables cloud inference.
Rule 6
SharedArrayBuffer Headers
COOP + COEP headers required for crossOriginIsolated === true. Must be present in server.js (dev), vercel.json (prod), and sw.js (fallback). Never remove them.
Rule 7
STAGES & SLIDER_REGISTRY Location
Both data structures live in slider-map.js only. app.js imports them: import { SLIDER_REGISTRY, STAGES } from './slider-map.js';. slider-map.js is a pure data module — no Web Audio API, no SharedArrayBuffer, no side effects.

Total: 6+5+10+8+8+6+5+4 = 52 — enforced by scripts/validate.js + tests/sliders.test.js

Adding a Slider — Checklist

  1. Add the object to SLIDERS in app.js
  2. Add a corresponding entry to SLIDER_REGISTRY in slider-map.js
  3. Add the ID with a default value to every preset in PRESETS
  4. Update tests/sliders.test.js if count or tab changes
  5. Update tests/presets.test.js if preset completeness check fails

Service Worker

sw.js is registered by sw-register.js and handles:

  1. COOP/COEP header injection → crossOriginIsolated === true for SharedArrayBuffer
  2. App-shell pre-caching on install (all static JS/CSS/HTML assets)
  3. Cache-first strategy for ONNX model files (vip-models-v1 cache)
  4. Network-first strategy for index.html (always fresh)
  5. Zero-downtime updates via skipWaiting + clients.claim on activate
scripts/stamp-sw-version.js injects a cache-bust version string into sw.js at Vercel build time.

Audio Buffer Rules

  • Always use Float32Array for audio data in hot paths
  • Use setTargetAtTime() for smooth AudioParam transitions (not setValueAtTime())
  • In-place spectral operations — never copy the entire spectrum array
  • Ring buffer pattern (ring-buffer.js) for main thread ↔ AudioWorklet shared memory

Common Pitfalls

READ FIRST
01Don't load ONNX Runtime from CDN. Always /lib/ort.min.js. Run pnpm setup:ort if missing.
02Don't load Three.js from CDN. Always /lib/three.module.min.js via importmap. Run pnpm setup:three if missing.
03Don't add a second STFT/iSTFT. All spectral work goes in stages 10–20. Applies to offline-processor.js and any new modules.
04Don't spawn the ML worker from app.js. Only pipeline-orchestrator.js owns worker lifecycle.
05Don't remove COOP/COEP headers. SharedArrayBuffer breaks without them (server.js, vercel.json, sw.js).
06Don't add presets without covering all 52 slider IDs. tests/presets.test.js will fail.
07Don't add sliders without updating every preset AND SLIDER_REGISTRY. Both tests/presets.test.js and tests/slider-map.test.js validate completeness.
08Use pnpm, not npm or yarn. This repo is documented and tested around pnpm; verify current repo config before assuming package-manager enforcement.
09Tests use CommonJS (require); frontend uses ESM (import). Don't mix them.
10public/lib/ files ARE committed. ORT WASM, ort.min.js, and three.module.min.js are git-tracked. Do not add public/lib/ to .gitignore.
11build/ is gitignored — generated by pnpm build. Never commit build output.
12<script type="importmap"> must appear before any <script type="module"> in index.html. Reordering breaks Three.js / 3D spectrogram.
13STAGES and SLIDER_REGISTRY live in slider-map.js, not app.js. Import, don't redefine.
14Some ONNX models are committed; some are Blob-hosted. Silero VAD, RNNoise, BSRNN are committed. Demucs v4 uses .placeholder — fetched from Vercel Blob on first use.
15Node.js 24.x is required. Follow the version declared elsewhere in the repo and CI, and do not assume .npmrc currently enforces it locally. Don't test with Node 20 or earlier.
16vip-slider-patch.js loads LAST — it patches slider state after app.js initializes. Load order in index.html is critical; do not move it earlier.
17debug-audit.js is console-only — call window.VIP_runAudit() from DevTools. Do not wire it into the normal app boot path.
