VoiceIsolate Pro Architecture

HOW IT WORKS

Privacy-first local processing

One forward STFT. In-place spectral work. One inverse STFT.

VoiceIsolate Pro keeps audio inside the browser. Uploaded files (and optional video) are decoded locally, cleaned in the time domain, routed through a single spectral pass, reconstructed once, and then polished in an OfflineAudioContext and playback-only AudioWorklet chain (Gate + De-Esser). Product workflow is upload-only — no microphone. No cloud inference, no audio telemetry, and no server-side audio processing are introduced in the active pipeline.

Execution paths

  • Live-Mix path: After offline separation, playback uses AudioParams + Gate/De-Esser worklets only (no ML on the audio render thread).
  • Creator / Studio / Forensic path: OfflineAudioContext / worker render for deeper cleanup and export-ready output.
  • ML path: ONNX Runtime Web loads same-origin model assets, preferring WebGPU with WASM fallback.

Engineer controls

The Engineer Mode panel exposes grouped controls for gating, NR, EQ, dynamics, spectral shaping, separation, advanced restoration, and output management. Sliders stay wired to the active transport state, A/B compare, diagnostics cards, and the processing rail.

Why the single-pass spectral rule matters

Additional STFT → iSTFT round-trips smear phase, soften transients, and introduce watery artifacts. VoiceIsolate Pro preserves phase coherence by doing spectral operations in-place between one forward transform and one inverse transform.

Privacy and local guarantees

  • No external audio uploads during processing.
  • No telemetry that includes user audio.
  • Models are fetched from same-origin assets and cached locally for repeat runs.
  • SharedArrayBuffer isolation stays protected by COOP/COEP headers.
